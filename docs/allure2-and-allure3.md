# Allure 2 and Allure 3

The default `compatibility: allure2-and-3` writes the stable official Allure 2 result model: `*-result.json`, `*-container.json`, attachments, `environment.properties`, `executor.json`, and `categories.json`. Allure 3 supports this result input, so one directory can be generated by either CLI.

```console
allure generate reports/allure-results --clean -o reports/allure2
npx -y allure@3.14.3 generate reports/allure-results -o reports/allure3
```

Install Allure 2 from the official 2.45.0 GitHub release archive. `scripts/test-allure.ps1` and `scripts/test-e2e.sh` verify its published SHA-256 before execution because the `allure-commandline` npm wrapper can lag the upstream CLI release.

`compatibility: allure3` is an explicit policy switch reserved for optional Allure 3-only additions. Version 0.1.0 intentionally emits no incompatible extension fields in either mode.

## Conformance expectations

A release candidate must:

1. generate the exhaustive Gauge Python result directory;
2. run both pinned generator commands successfully;
3. verify each output contains `index.html`;
4. retain the native result directory as a CI artifact;
5. inspect generated data for nonzero passed, failed, broken, and skipped counts.

Allure CLI version bumps are compatibility changes and go through the nightly matrix before becoming required. The official Go model dependency is isolated behind the repository’s writer interface; changing it requires golden-test review.

## History

To preserve trends, copy the previous report’s history directory according to the selected Allure deployment workflow before generation. Reporter `historyId` is stable across machines and retries, but changes when non-excluded logical table/parameter values change.
