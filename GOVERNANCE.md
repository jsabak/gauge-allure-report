# Governance

Gauge Allure Report uses a maintainer-led, consensus-seeking model.

Maintainers triage issues, review changes, manage releases and security, enforce community standards, and represent the project in Gauge repository submissions. Routine changes require one approving maintainer and passing required checks. A maintainer cannot be the sole reviewer of a security-sensitive change they authored when another active maintainer is available.

Protocol, identity, compatibility, security, governance, and irreversible distribution decisions require a documented ADR or governance proposal with a public comment period appropriate to project activity. Maintainers seek consensus; if it cannot be reached, the lead maintainer decides and records rationale.

New maintainers are selected based on sustained technical/community contributions, sound security judgment, and Code of Conduct alignment. Existing maintainers approve additions. Inactive maintainers may move to emeritus status after consultation. Current roles are listed in [MAINTAINERS.md](MAINTAINERS.md).

Release authority does not imply authority to bypass tests, artifact verification, DCO, disclosure policy, or branch protections. Project assets and credentials should use least privilege and more than one recovery path when the project gains multiple maintainers.
